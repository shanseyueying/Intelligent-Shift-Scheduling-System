# 智能排班辅助系统

基于 **Python + Streamlit** 的月历排班工具。目标不是简单地把班表画出来，而是把排班过程变成“校验 → 评分 → 对比 → 推荐调班”的可解释工作流。

> 已有功能：数据底座、独立月历模块、未安排/休息/班次三态单日编辑、周期模板预览/铺排与受控覆盖、硬约束预检、人员/班次/请假配置、覆盖组缺岗规则、软归档、多方案管理、请假冲突清理、健康评分看板、方案差异对账、Top 3 调班推荐、单条硬约束智能修复、加权负荷统计看板和 CSV 宽表导入导出。侧边栏提供当前方案快捷切换。

## 技术栈

- Python 3.10+
- Streamlit 1.65
- streamlit-calendar 1.4（FullCalendar 封装）
- Pydantic 2（严格数据校验）
- Pandas 2（统计与差异表）
- Altair 6（加权负荷堆叠图，经 dataviz 色板校验）
- pytest（约束与算法测试）
- 本地 JSON（配置与方案分文件）

## 目录结构


## 快速开始

Windows PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
streamlit run app.py
```

Git Bash：

```bash
python -m venv .venv
source .venv/Scripts/activate
python -m pip install -r requirements.txt
streamlit run app.py
```

首次启动且 `data/` 为空时，会生成 4 名示例人员、早/中/夜 3 个班次和一个空白方案。

## 使用方式

- **单日编辑**：月历位于 Tab 1 顶部；点击任意日期或已有事件，或使用月历下方的“手动编辑日期”入口，弹窗中为启用人员选择“未安排/休息/班次”，并可填写当天交接备注。“未安排”可被模板补齐，“休息”会写入方案并锁定该格。
- **日历布局**：方案概览、硬约束/缺岗提示、缺岗明细、排班明细和周期模板都在月历下方，日历不再被预警信息挤到页面下方。
- **侧边栏**：显示艺术化系统标题、当前方案与“切换方案”快捷按钮；数据目录折叠在“数据与存储”中，减少侧边栏占用。切换方案会同步 Tab 2 的方案选择器。
- **周期模板**：展开日历下方的“周期模板铺排”，选择参与人员、起止日期与 1–14 天循环矩阵。默认只补空白并写入显式休息，不覆盖已有班次/休息；需要批量修正旧班表时，显式勾选“覆盖选中人员在该区间的已有排班和休息”，预览并二次确认后才应用。模板只修改所选范围，开始日期之前的日期不会被自动对齐；范围外某天请点击日历或使用手动编辑日期单独修改。
- **冲突预检**：模板预览会列出新增的“夜班后次日早班”冲突；默认需要勾选确认才能继续应用。
- **基础配置**：在 Tab 4 通过列表 + 弹窗新增/编辑人员、班次、缺岗覆盖组和请假。人员/班次使用软归档；请假记录删除前有确认弹窗。
- **缺岗覆盖组**：把可以互相替代的班次归入同一组（例如白班/早班/中班同属“日班组”），组内人数合并计算；未入组的班次继续按自己的最低人数检查。
- **请假避让**：新排班和模板自动跳过请假人员；已有冲突在日历下方和健康分中提示，可在 Tab 2 预览后移除当前方案的冲突班次。
- **多方案**：在 Tab 2 顶部或侧边栏快捷按钮切换方案；新建、复制、重命名仍集中在 Tab 2。每次切换会同步更新 `settings.json` 中的活动方案 ID。
- **健康与缺岗**：Tab 2 显示硬约束、软约束扣分明细、整体健康分，以及按覆盖组/班次最低人数的缺岗表。
- **统计看板**：Tab 3 展示 KPI、按班次堆叠的加权负荷横向柱图、偏好满足、请假天数和显式休息天数明细，统计包含全部启用人员。
- **方案对比**：选择任意参考方案，以 `(日期, 人员)` 为键展示新增、删除、变更（含显式休息）和交接备注差异，并汇总两方案健康分、硬约束、缺岗和偏好满足率。
- **调班推荐**：在 Tab 2 选择高负荷人员，只交换双方已有的启用班次；候选必须无硬约束、目标人员负荷下降且健康分不倒退，按负荷下降量返回 Top 3，确认后应用并记录审计。
- **单条智能修复**：在“夜班后次日早班”违规行点击“尝试智能修复”，优先寻找两两换班；没有可行交换时，才寻找当天空闲的启用人员接手早班。只呈现一个最佳预览，必须同时消除选中违规且不新增硬约束。
- **CSV 导入导出**：在 Tab 4 底部将当前方案导出为宽表 CSV；上传 CSV 后先做结构、日期和引用校验，显示警告与数据预览，确认后创建独立新方案并自动切换，原方案保持不变。
- **安全落盘**：确认操作后才会写入方案/配置文件；每次覆盖旧文件前自动备份。

## 数据安全设计

- **配置与方案分文件**：单个方案损坏不会波及其他方案。
- **写入前校验**：所有落盘对象都经过 Pydantic；未知字段会显式报错。
- **原子写入**：先写同目录临时文件，`fsync` 后用 `os.replace` 替换。
- **覆盖前备份**：旧文件自动复制到 `data/backups/`，每个文件保留最近 10 份。
- **拒绝危险 ID**：方案 ID 会做文件名安全校验，防止路径穿越。
- **不自动清理方案**：发现损坏或不一致时停止并提示，不会用空数据覆盖。
- **设置丢失保护**：如果存在方案文件但 `settings.json` 丢失，应用拒绝自动重建配置。
- **软归档**：停用人员/班次不从历史方案中物理删除；它们后续不再出现在新排班和模板中，可随时恢复。

## 已实现的业务约束与算法

- 同一天同一人最多一个班次（模型层直接禁止重复人员安排）。
- **夜班后次日禁止早班**：用班次显式属性识别早晚班；按人员、日期排序后只检查日期差为 1 天的记录，不依赖班次名称。手动编辑会警告新增冲突；模板预览会标出新增冲突并要求确认。
- **请假锁定**：请假人员不会进入新排班和模板候选；请假期间已有安排会作为硬约束标红。清理仅作用于当前方案，需在预览弹窗确认，且写盘前自动备份。
- 模板默认只填充空白“日期 + 人员”格，并写入显式休息；已有排班、休息和交接备注一律保留。显式休息与“未安排”是两种状态，重新套默认模板不会把休息日填成班次。只有勾选覆盖模式并二次确认后，才会替换选中人员在该区间的已有状态。
- 每次预览绑定当前方案更新时间与模板参数指纹，方案或参数变动后旧预览不能直接应用。
- 班次不能同时标记为早班和夜班；请假区间、人员偏好、引用完整性和时间戳均由 Pydantic 校验。
- **缺岗覆盖组**：启用组内的班次人数合并计算；同一班次不能同时属于两个启用中的覆盖组；停用组会回退为逐班次检查；未入组班次保持原有 `min_staff` 行为。
- 模板单次最多铺排 92 天、循环周期 1–14 天，控制预览数据量与算法开销。
- 日历组件单独封装，只在日历 Tab 激活时挂载，避免隐藏 Tab 中以零宽宽度初始化后切回时显示空白。

### 健康分公式（均衡型）

| 维度 | 规则 | 上限 |
|---|---|---:|
| 硬约束 | 夜班→次日早班、请假冲突；任一违规 → 总分 0、状态“不合格” | 一票否决 |
| 连续同班次 | 同人同班次连续 ≥3 天，从第 3 天起每天扣 2 分 | -20 |
| 负荷均衡 | 有排班人员的加权负荷极差 × 5 | -25 |
| 偏好满足 | 有偏好人员的未满足排班比例 × 20 | -20 |

健康分 = `max(0, 100 - 三项软约束扣分)`；无排班数据时显示“暂无排班”而不是 100 分。  
状态阈值：≥85 健康，≥70 需要关注，其余需要优化；有硬约束直接“不合格”。  
缺岗预警只检查方案中已有排班或备注的日期，不参与健康分。

### 缺岗覆盖组

原来的缺岗预警把每个启用班次当成独立岗位，逐一检查 `min_staff`。例如早班/中班/夜班各要求 1 人时，即使白班可以替代早班+中班，排“白班+夜班”仍会误报早班和中班缺岗。

现在可以在基础配置中创建覆盖组：

| 配置 | 示例 |
|---|---|
| 覆盖组 | 日班组 |
| 组内班次 | 白班、早班、中班 |
| 组最低人数 | 1 |
| 覆盖组 | 夜班组 |
| 组内班次 | 夜班 |
| 组最低人数 | 1 |

- 组内所有启用班次的排班人数合并计算，达到组最低人数即视为该组不缺岗；
- 未加入任何启用组的班次，继续按自身的“最低在岗人数”单独检查；
- 停用覆盖组后，组内班次回退到各自的 `min_staff`；
- 同一班次只能属于一个启用中的覆盖组，避免重复计数；停用组之间可以重叠，恢复时会重新校验；
- 组最低人数为 0 表示暂不检查该组；组内所有班次都停用时，该组不产生无法满足的缺口。

### 调班推荐算法

1. 只针对启用人员、启用班次和双方已有的班次做两两交换，不新造岗位；
2. 先按目标人员潜在加权负荷下降量贪心预筛，最多对 400 个交换对做完整评估；
3. 每个候选都完整检查硬约束，并计算交换后的健康分；
4. 过滤掉目标负荷未下降、存在硬约束、或健康分低于当前的候选；
5. 在剩余候选中按“目标负荷下降量 → 健康分”排序，返回 Top 3；
6. 应用时再次校验方案与配置指纹，成功后写入 `history_audit` 并自动备份。

### 单条硬约束修复算法

1. 只支持“夜班后次日早班”违规；请假冲突继续使用单独的批量清理预览；
2. 先尝试涉及违规早班/前夜班的已有班次互换，保持岗位数；
3. 完全没有可行交换时，才寻找当天未排班、未请假的启用人员接手早班作为兜底；
4. 每个候选必须让选中违规消失，且不能新增任何硬约束；其他既有违规可暂时保留；
5. 在候选中按剩余硬约束数、软约束扣分选出最佳，只展示一个预览，确认后才落盘。

### 休息与模板覆盖

排班现在区分三种“日期 + 人员”状态：

| 状态 | 含义 | 模板默认行为 |
|---|---|---|
| 未安排 | 尚未决定，可被模板补充 | 可填入班次或休息 |
| 休息 | 明确安排休息，已持久化 | 保留，不自动填充 |
| 班次 | 已安排具体班次 | 保留，不自动覆盖 |

默认模板会为周期中的 `休息` 格写入显式休息标记，因此重复套用默认模板不会再把休息日误填成班次。需要批量修正旧班表时：

1. 在周期模板中设置正确的班次/休息矩阵；
2. 勾选“覆盖选中人员在该区间的已有排班和休息”；
3. 生成预览，逐条核对“原状态 → 新状态”；
4. 勾选覆盖确认后应用。

覆盖只作用于选中人员和日期区间，其他人员的安排与当天交接备注保持不变；预览绑定当前方案和模板参数，方案变化后必须重新生成。

### CSV 导入导出

CSV 使用“日期 × 人员”的宽表，便于用 Excel 批量交接，也便于从旧表格迁移数据：

```csv
日期,人员:张三,人员:李四,交接备注
2026-11-02,早班,,设备钥匙已交接
2026-11-03,,夜班,
2026-11-04,休息,早班,消防通道已检查
```

- **导出**：Tab 4 底部“下载 CSV”。列顺序为 `日期`、全部启用人员（含历史方案中引用的停用人员）、`交接备注`；空白格表示“未安排”，`休息` 表示显式休息。文件使用 UTF-8 BOM，Excel 打开中文不会乱码。
- **导入**：人员列推荐使用 `人员:姓名`，也接受直接写已知人员姓名；`日期` 必须为 `YYYY-MM-DD`，`交接备注` 可选且最多 1000 字。单元格填写班次名称；留空表示未安排，填写“休息”会导入为显式休息，并锁定该格不被默认模板填充。
- **校验**：支持 UTF-8（推荐）与 GB18030；文件不超过 2 MB、数据不超过 5000 行。重复日期/列、未知人员或班次、无效日期、列数不一致等会拒绝导入并列出错误，不创建任何文件。
- **警告**：允许导入当前配置中已停用的人员/班次，但会提示；`夜班后次日早班`、请假冲突等硬约束只作为警告展示，导入后健康分会标为“不合格”，可再使用智能修复处理。
- **安全边界**：导入只创建带 `csv_imported` 审计记录的新方案，名称必须唯一；保存成功后才切换活动方案。原方案、备份和其他方案不受影响；校验或保存失败不会覆盖现有数据。
- **界面预览**：最多展示前 30 天数据（实际导入全部行），并在导入前展示硬约束违规明细；导入成功后自动清空上传控件，避免误重复导入。

## 已知限制

- CSV 只包含排班、显式休息与交接备注，不包含人员、班次、覆盖组、请假配置；导入时使用当前配置做引用校验，未知人员/班次不会自动创建。CSV 导入也只支持创建新方案，不支持追加或合并到现有方案。
- 覆盖组启用时，组内班次自己的“最低在岗人数”不再单独生效，以组最低人数为准；覆盖组采用停用/恢复管理，不物理删除，避免误操作改变历史复盘口径。
- 显式休息不计入排班人次和加权负荷，只在日历、明细、方案对比和统计表的“休息天数”中展示。
- 调班推荐只支持已有班次互换，不支持把班次转给休息人员；智能修复的“替补兜底”也不会把班次派给显式休息人员。缺岗作为独立预警展示，不作为推荐候选的过滤条件。
- 统计图使用固定的高对比度分类色板，不复用配置页中用户自定义的班次颜色，以保证色盲可读性。
- 手动编辑仍可保存新的夜班→次日早班冲突（会显示警告），方便先保存草稿再统一修复；模板铺排新增冲突需要显式确认。
- 缺岗预警只覆盖方案已有排班、显式休息或备注的日期；空白未来日期不会被提前判为缺岗。
- 请假冲突清理一次只处理当前方案，其他方案中的冲突会在切换到该方案时提示。
- 当历史排班涉及已停用人员/班次时，该部分安排会在单日编辑弹窗中只读保留；需恢复对应配置后才能修改。
- 当前只支持整天请假；模板最长 92 天；日历组件采用非商业许可的 FullCalendar 封装，正式商用前需重新评估授权。
